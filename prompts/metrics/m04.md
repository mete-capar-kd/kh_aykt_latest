# m04 — Veri Yönetimi ve Entegrasyon Standartları

## Amaç

Veri tutarlılığını ve iç/dış entegrasyonların hata koşullarındaki dayanıklılığını gerçek uygulama akışı üzerinden değerlendirmek.

## Kontrol kapsamı

- Veritabanı erişim standartları
- migration yönetimi
- transaction kullanımı
- timeout ve retry politikaları
- API istemci yönetimi
- kişisel/hassas veri kullanımı
- harici servis bağımlılıkları ve API versioning

## Kabul kriterleri

- veri tutarlılığı veya entegrasyon dayanıklılığı etkisini açıklamalı
- ilgili kod bloğunu göstermeli
- genel öneri yerine teknik çözüm sunmalı
- retry önerirken idempotency riskini dikkate almalı.

## Tipik ihlaller

Kısmi yazım riski, sınırsız dış çağrı, kontrolsüz retry, istemci yaşam döngüsü hatası, sahipsiz migration ve versiyonsuz kırıcı API tipik adaylardır.

## Meşru istisnalar

Tek atomik işlem, doğal idempotent okuma, framework yönetimli istemci veya migration sorumluluğu başka bir deployable'da olabilir. Bulgu öncesinde kullanımın neden meşru olabileceğini incele ve `rationale` alanına yaz.

## Kabul edilen kanıt

Transaction sınırı, veri erişim çağrısı, istemci kaydı, retry/timeout policy'si, migration dosyası ve route/version tanımı gibi doğrulanmış satırlar kabul edilir.

## Belirsizlik ve yetersiz kanıt

Harici servisin SLA veya runtime davranışını uydurma. Repository akışı etkiyi göstermiyorsa `Kanıt yok` veya uygun confidence kullan.

## Kesin / potansiyel

Kod akışı tutarsızlık veya dayanıklılık açığını doğrudan gösteriyorsa `kesin`; dış servis davranışına bağlıysa `potansiyel` kullan.

## Metriğe özel davranış

Retry önerisini operasyonun idempotency özelliğiyle birlikte değerlendir. `standardRef` değerini `UseCase §6.4 — <alt kontrol>` biçiminde yaz; öneride somut transaction, timeout, client veya versioning çözümünü belirt.

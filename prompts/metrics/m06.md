# m06 — Test ve Kod Kalitesi Standartları

## Amaç

Testlerin yalnız varlığını değil davranış doğrulama gücünü, kritik akış kapsamını ve sürdürülebilir kalite kapılarını değerlendirmek.

## Kontrol kapsamı

- Unit ve integration testlerin varlığı
- kritik iş kurallarının test edilmesi
- test projesi yapısı
- mock kullanımı
- SonarQube yapılandırması
- code coverage
- cyclomatic complexity
- duplicate code ve testlerin pipeline içinde çalıştırılması

## Kabul kriterleri

- yalnızca test dosyası sayısına bakmamalı
- assertion kalitesini değerlendirmeli
- kritik akışların test edilip edilmediğini değerlendirmeli
- quality gate durumunu değerlendirmeli
- test piramidine uygun iyileştirme ihtiyacını değerlendirmeli.

## Tipik ihlaller

Assertion içermeyen test, yalnız happy-path kapsamı, davranışı gizleyen aşırı mock, pipeline'da atlanan test ve etkisiz quality gate tipik adaylardır.

## Meşru istisnalar

Generated code, veri taşıyıcıları, framework glue kodu veya daha yüksek seviyede doğrulanan ince adapter için doğrudan unit test gerekmeyebilir. Bulgu öncesinde durumun neden meşru olabileceğini değerlendir ve `rationale` alanına yaz.

## Kabul edilen kanıt

Test gövdesi ve assertion, üretim akışıyla eşleşen senaryo, test proje tanımı, coverage/quality yapılandırması ve pipeline test adımı kabul edilir.

## Belirsizlik ve yetersiz kanıt

Dosya sayısından coverage ya da kalite sonucu çıkarma. Rapor veya pipeline görünmüyorsa oran ve gate durumu uydurma.

## Kesin / potansiyel

Etkisiz assertion veya pipeline atlaması doğrudan görülüyorsa `kesin`; runtime coverage ya da karmaşıklık ölçümü gerekiyorsa `potansiyel` kullan.

## Metriğe özel davranış

Test piramidini uygulamanın risk ve sınırlarına göre yorumla. `standardRef` değerini `UseCase §6.6 — <alt kontrol>` biçiminde yaz; kritik akışla test kanıtı arasındaki ilişkiyi göster.
